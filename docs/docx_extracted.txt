PROJECT 01
DESIGN AND IMPLEMENTATION OF A DATABASE MANAGEMENT SYSTEM FOR STUDENT AND COLLEGE MANAGEMENT SYSTEM
Description:
This project involves the design and development of a relational database management system for a Student and College Management System. Colleges often maintain admissions, programme registration, courses, attendance, examinations, grades and fee records in separate files, causing duplication and delayed reporting. Students will analyse the requirements and identify the major entities, attributes, relationships and user roles. The conceptual design should represent students, guardians, departments, programmes, courses, faculty, semesters, registrations, attendance, examinations, grades, fee bills and payments. The ER model must be converted into a relational schema and normalized up to Third Normal Form (3NF). The database may be implemented using MySQL, PostgreSQL or Oracle with suitable primary keys, foreign keys, UNIQUE, NOT NULL, CHECK and DEFAULT constraints. Important business rules include unique registration numbers and course codes, valid marks and attendance ranges, no duplicate course registration, section-capacity control and payment limits. Students should populate the tables with realistic sample data and prepare SQL statements for data retrieval, joins, aggregate functions, nested queries, views and meaningful reports such as student-wise academic history, course registration, attendance shortage, result analysis, fee dues and department summaries. A small front-end application developed using Java or Python should support student admission, course registration, attendance entry, grade processing, fee collection, search and academic reporting. The work should demonstrate normalization, data integrity, transaction awareness, indexing of frequently searched attributes, input validation and systematic testing.
Deliverables:
Review 1 - Week 7 - 5 Marks
Problem identification, scope, objectives, users and functional requirements.
Conceptual design / ER diagram covering the principal entities: students, guardians, departments, programmes, courses, faculty, semesters, registrations, attendance, examinations, grades, fee bills and payments.
Initial relational schema showing proposed tables, primary keys and relationships.
Review 2 - Week 11 - 5 Marks
Normalized database design up to 3NF with functional dependencies and a concise data dictionary.
DDL scripts with applicable integrity constraints to enforce: unique registration numbers and course codes, valid marks and attendance ranges, no duplicate course registration, section-capacity control and payment limits.
Sample data and SQL queries demonstrating joins, subqueries, aggregation and views for: student-wise academic history, course registration, attendance shortage, result analysis, fee dues and department summaries.
Implementation progress and database prototype demonstration.
Review 3 - Week 16 - 5 Marks
A simple Java or Python application connected to the designed database for student admission, course registration, attendance entry, grade processing, fee collection, search and academic reporting.
Final project demonstration showing CRUD operations, search, validation, reports and error handling.
Source code, database script, test data, output screens, project report and viva-voce.
